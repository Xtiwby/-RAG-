# 预训练语义向量与模型重排（v0.9）

## 技术路线

Vue 3 + FastAPI 保持不变。共享检索入口升级为：

授权与最新文档版本过滤 → 可选双语改写/子问题 → BGE-M3 稠密语义向量与 BM25 → RRF 融合 → BGE-reranker-v2-m3 Cross-Encoder → 主题覆盖约束与 TopK → 生成 → 原有事实与引用核验。

关键词模式不调用 Embedding；选择模型重排时，关键词模式也可重排其自身候选。关闭重排仅跳过重排阶段，不改变检索后端。双语改写不是语义向量的替代品，也不是回答证据。

## 本地模型

| 用途 | 模型 | 固定官方提交 |
|---|---|---|
| 1024维、CLS池化、L2归一化的语义向量 | BAAI/bge-m3 | 5617a9f61b028005a4858fdac845db406aefb181 |
| 联合读取问题与片段的Cross-Encoder | BAAI/bge-reranker-v2-m3 | 953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e |

模型卡：[BGE-M3](https://huggingface.co/BAAI/bge-m3)、[BGE-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)。本版只使用BGE-M3的稠密向量能力，不宣称已接入它的稀疏向量或ColBERT能力。

模型保存在 `backend/models/`，不提交到版本库。本机配置为RTX 4060 Laptop 8GB；CUDA版PyTorch自动选择显卡，CUDA推理采用FP16，CPU采用FP32。Embedding与重排共享设备锁，在后台线程串行推理，避免阻塞FastAPI事件循环及多任务争抢显存。设置为“仅CUDA”时，不支持CUDA会明确报错。

运行时仅加载本地safetensors，禁止远程代码与在线自动下载。准备脚本通过hf CLI下载固定版本的配置与分词器，校验Git blob/LFS哈希；权重还与代码固定的SHA256比对。官方BGE-M3提供的bin权重在校验后用`torch.load(weights_only=True)`读取，再原子转换为safetensors。下载未完成不会发布manifest。

官方站不可直连时，可从ModelScope的BAAI同名仓库下载字节一致的权重，仍必须通过固定官方权重哈希；这不是替换模型或向外部服务发送知识库。

## 安装与启用

本机已经准备依赖与模型；下列命令用于其他环境重新部署。示例均在backend目录的PowerShell中运行。

```powershell
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -m pip install -r requirements-models.txt
.\.venv\Scripts\python.exe prepare_models.py
```

网络受限时：

```powershell
$env:HF_ENDPOINT='https://hf-mirror.com'
$env:HF_HUB_DISABLE_XET='1'
.\.venv\Scripts\python.exe prepare_models.py --source modelscope
```

本机另保留已核验SHA256的PyTorch安装包于`backend/data/installers/`。CUDA版本应与实际驱动和平台适配，不要在其他平台直接复制本机Windows安装包。

在“系统配置”中保存：

- Embedding后端：local；模型：BAAI/bge-m3；默认每批8条、最大2048 Token。
- 重排后端：local；模型：BAAI/bge-reranker-v2-m3；默认候选40条、每批4对、最大1024 Token。
- 默认检索：hybrid；保留BM25、RRF、现有TopK与证据门槛。
- 分别点击向量和重排的检测按钮。这两个检测实际执行推理，不仅检查文件存在。

本机已上线后端0.9.0，配置版本4；两个模型均通过运行中服务的CUDA真实推理检测，前端5173代理也指向新版。补齐了1226条语义向量缓存，旧文档、片段、会话、报告与授权逐字段保护检查通过。

原有`cross_language=true`保留。实际上线搜索测试中，包含较多代码的Vue资料被识别为混合语言，因此额外调用了一次Kimi双语改写，整体检索耗时约18.4秒；这不是本地模型本身的耗时。管理员可在配置中关闭该可选辅助以减少外部调用。上述96次模型能力验证明确关闭改写，没有生成模型调用。

新上传文档在索引提交前计算语义向量。既有文档首次检索时补齐向量缓存，不重建文档、片段或历史引用。缓存命名空间包含模型、固定提交、池化版本和输入长度，切换配置不会混用不同维度。测试脚本也支持仅将已验证的缓存补入正式库。

旧配置和旧任务快照缺少新增字段时仍按原词项基线解释；不会在未下载模型的环境中擅自启用新后端。当前实例通过带配置版本校验的设置接口明确切换。

## 可观测性与边界

- 搜索、问答历史、报告章节预检查保存实际Embedding与重排模型、候选数量、运行设备、模型提交及输入上限信息。
- `model_calls`区分embedding和reranking，记录耗时、失败和中止。本地推理不产生Kimi调用费用。
- 重排采用sigmoid后的相关性得分，它不是事实正确概率；是否有证据支持仍由生成后的核验流程判断。
- 重排达到输入长度上限时会显示提示；原文片段不截断、不改写，引用版本不变。
- 纯语义候选不再要求中英词项交集，但仍经过语义阈值、知识范围和版本过滤。复合问题/显式主题覆盖在模型候选池内执行，不从池外加入未经模型评分的片段。
- 模型缺失、显存不足、超时或响应数值异常时明确失败，不把TF-IDF或词项重排冒充模型结果。超时只能停止等待，已提交给线程的CUDA计算可能继续到本批结束。
- 模型变更使旧报告预检查失效，需重新检查；旧草稿、正式报告和引用不会因此重写。用户仍拥有审阅与定稿权。
- 目前仍是SQLite向量缓存+授权片段余弦扫描，不是ANN向量数据库；数据量增大后再升级索引基础设施。

## 验证方法

本轮隔离回归82项通过，新增15项覆盖语义调用、模型得分改变排序、开关、缓存、非法得分、撤权、报告共用入口及索引失败保护。前端构建及6项既有账户表单测试通过；后两者不是模型质量结论。

真实CUDA合成测试：中文“空气中的水分如何去除？”对应英文除湿机原理片段的余弦相似度约0.614，两个无关片段约0.278/0.328；Cross-Encoder得分约0.891，两个无关片段均低于0.00002。两个模型均在RTX 4060上实际执行，未调用双语改写。

固定10份资料、32题、TopK=5，关闭双语改写，完成96次真实本地检索：

| 模式（均开启模型重排） | 全部指定来源命中/25道可答题 | 全部标准短引文连续命中/25 | 可答题平均检索耗时 |
|---|---:|---:|---:|
| 语义向量 | 25/25 | 18/25 | 2474ms |
| BM25关键词 | 19/25 | 15/25 | 518ms |
| 语义向量+BM25混合 | 25/25 | 18/25 | 2547ms |

这是开发集的来源/片段命中，不是答案正确率。7道无答案题仍可能返回相关但不足以支持目标事实的片段，不能根据“检索非空”判定可回答；本轮未重测真实Kimi生成与拒答质量。

在数据库快照上对原测试报告#14的章节执行真实共享检索：UploadFile节召回S03，pypdf/OCR节召回S10，均执行Cross-Encoder。项目QPS节仍只有外部教程候选，不构成项目实测证据。本轮不重新生成或发布报告。

真实验证首次运行在全部检索完成后遇到Windows临时SQLite连接未关闭、导致快照清理失败；已显式关闭连接，并完整重跑96次及章节检索成功。最终表格来自成功重跑结果。

隔离回归：`python -m pytest tests -q -p no:cacheprovider`。模型适配器在单测中模拟，不能替代真实质量验收。

真实本地推理：在项目根目录运行：

```powershell

```
