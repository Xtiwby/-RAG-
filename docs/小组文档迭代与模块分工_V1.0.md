# 知源 RAG 小组文档迭代与模块分工

## 1 分工原则

五名成员各自对一个责任域承担“需求、设计、代码、测试、演示”闭环责任。模板库与报告生成共用模板结构、字段映射和导出链路，合并为一个责任域；测试负责人独立检查各模块，不代替模块负责人编写本模块测试。

组长负责统一需求编号、版本和合并顺序。任何成员修改接口、数据库表、状态机或业务规则时，必须同步修改对应文档和确认矩阵，不能只提交代码。

## 4 本轮交付顺序

1. **需求冻结**：王凤琳组织确认全文报告、整篇重生成、音视频和重复文件术语，形成变更记录。
2. **模块更新**：四名模块负责人同时更新本模块需求、设计、代码定位和测试用例。
3. **设计合并**：周鑫合并系统设计，王韵涵合并详细设计，清理旧编号和旧流程。
4. **测试复核**：张心蕊执行自动化回归、性能记录和矩阵复核，问题退回对应负责人。
5. **基线发布**：王凤琳检查版本号、修订记录、文档链接和演示口径，完成一次组内评审后提交。

## 6 每名成员提交检查表

每个模块合并前必须同时提交：

- 本模块变更说明和关联需求编号。
- 更新后的需求、系统设计或详细设计段落。
- 接口、数据库和状态变化说明；无变化也要明确写“无”。
- 自动化测试结果；涉及模型或真实存储时附真实环境记录。
- 至少一个正常流程和一个异常流程的演示步骤。
- 尚未解决的问题、风险、依赖和下一步计划。

只有代码、没有文档和测试证据的提交，不计入本轮模块完成。
