# 第一轮质量改进交付（0.10.0）

日期：2026年11月1日。此文区分已实施、验证结果与后续待办，不代表三个迭代全部完成。

## 已实施

1. 数字检查区分BM25、FTS5、k1等标识符与事实数字；规范化小数、千分位和百分数，保留负号及百分号含义。引用中表达明确参数绑定时，检查参数与数值的对应关系。数字门禁仅是模型事实判断之外的辅助规则，不能证明事实必真。
2. PDF断词、软连字符、空白和Unicode排版差异在匹配层处理，不改原文件、原文、片段和哈希。核验引文保存原文实际子串、片段内起止位置和来源文本哈希。
3. 兼容合并引用`[1,2]`和部分Markdown闭合格式；句段切分保护代码标识符、属性访问和小数。内联代码中的数字数组不当作引用。不允许缺失引用的下一句借用上一句编号。
4. 核验区分supported、partial、contradicted、insufficient，部分支持仍不发布整句。记录原因码，区分引文不匹配、数字冲突、缺引用和服务故障。
5. 回答结束后可选执行一次问题关键点覆盖检查。发现有证据但遗漏的要点时，最多一次、默认最多4句补充；补充必须通过同一引用、事实、原文定位和数字门禁才发布。
6. 覆盖结果随SSE发送并持久化到问答消息，历史回答不补造记录。事实型报告章节共用检查，记录及导出包含关键点状态；分析、建议章节未启用自动完整性补写。旧报告不重生成，人工审阅与最终定稿权不变。
7. 主TopK之外可补相邻原文，默认最多4条，总证据最多20条。候选来自相同授权范围、相同最新可用文档；每条有自己的ID、版本、文本和哈希，不拼接成假片段。相邻上下文不伪装成独立重排结果，相关度记为0并明确标注“未独立评分”。
8. 新增质量配置及界面提示，默认兼容旧任务；当前实例通过配置接口明确启用。报告预检查签名纳入质量参数，配置变化后需重新检查，不沿用旧证据快照。

真实问答使用原网络资料、原问题、原授权知识库范围、主TopK=5；新增邻接上下文可使证据条数高于5，不能与旧版严格当作单因素对照。没有把标准答案送给生成或覆盖检查。保留了初次测试、无上下文复测及加上下文后的复测，不能混合挑选最好结果。

## 独立合成验收集

`test-data/quality-v010-synthetic/`包含20份虚构手册、100题（80可答、20无证据），已冻结文件哈希并通过结构校验。只有`corpus/`是语料，`labels/`不入库。

## 费用、失败与安全

- 覆盖检查增加一次Kimi调用；需要补充时再增加一次事实核验。仍可能出现较长等待及额外费用。配置可关闭覆盖检查或只关闭补充。
- 覆盖检查失败保留已经核验的答案，并标为无法确认完整；事实核验服务异常时，不触发未经核验的修补。
- 模型完整性判断会误判，Q025已证明这一点。正确引文与逐句核验也不构成绝对无幻觉保证。
- 生成、补充及检索完成后继续复核权限；测试覆盖补充期间撤权，不向已失权用户发布新增内容。
- 部分支持仍要求审阅，用户可接受风险定稿，模型核验状态不会因此变成通过。
- 聊天中曾明文提供的Kimi密钥仍应由用户在模型平台轮换；本轮未读取或展示密钥内容，未擅自更换凭据。

## 复现

在backend目录执行隔离测试：`python -m pytest tests -q -p no:cacheprovider --basetemp <全新项目内临时目录>`。不要把该参数指向已有资料目录，因为pytest可能清理临时目录。

项目根目录：

```powershell
.\backend\.venv\Scripts\python.exe backend/validate_quality_acceptance.py
.\backend\.venv\Scripts\python.exe backend/check_quality_v010.py preserve
```

`check_quality_v010.py configure`会显式保存配置；`qa`会产生真实模型费用及标注测试会话。默认跳过已有同名结果，使用`--run final`或`--run trial2`区分批次；原始结果不得冒充新代码复测。`check_quality_repair_v010.py`在临时数据库中验证有限补写，仍会调用真实Kimi。

本机备份为`backend/data/backups/pre-quality-v010-20261101.db`，包含敏感账户数据，只限本机保存。
