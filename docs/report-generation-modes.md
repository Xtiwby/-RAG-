# 报告生成的两种模式

在“报告中心 → 新建报告 → 报告需求”选择生成模式，然后选择已发布模板、授权知识库并检查证据。两种模式共用模板排版，均支持草稿编辑、单节重生成、审阅和 DOCX/PDF/Markdown 导出。

| 模式 | 生成过程 | 适用内容 |
| --- | --- | --- |
| 严格事实证据（默认） | RAG检索，Kimi生成候选，逐句引用与独立事实核验，保留支持的句段 | 事实汇总、来源摘编、审计报告 |
| 基于证据综合生成 | RAG检索，将资料、章节要求和目标字数交给Kimi，生成连贯正文并检查引用编号 | 实验方案、原理说明、综合分析、建议报告 |

综合生成允许对资料归纳、解释和提出方案，不强制每句话进行独立事实核验。模型需要为关键事实附上来源编号，并明确标注推断和建议。服务端检查引用是否存在，不把有效编号等同于事实已经核实。正文保留“未执行逐句事实核验”的状态，必须人工审阅后再决定定稿。

对于CS336等作业资料，可在综合生成模式填写：“根据知识库中的实验要求，介绍实验原理、任务目标、实现步骤、评测方法和预期观察。区分题目原始要求与建议实现方案。没有提供运行日志的实验结果保留待实测，不编造耗时、准确率或已完成进度。”

没有候选证据时，两种模式都保留待补充标记，不用模型常识填充实验结果。综合生成出现无引用、无效编号、空响应、超长正文或服务故障时，任务报告错误；单节重生成不覆盖已保存正文。

模式在创建报告时保存到任务参数和模板快照，参加预检查签名。切换模式后需要重新检查证据。单节重生成沿用报告模式，重试、正式发布快照和导出保留模式。历史报告缺少模式字段时按严格模式处理，不重写历史正文。

API：`POST /api/reports/preflight`、`POST /api/report-tasks` 接受 `generation_mode`，值为 `strict` 或 `synthesis`，省略时使用 `strict`。`GET /api/reports/{id}` 返回当前模式。

手动点击“核验当前正文”仍会执行事实核验。这是额外操作，不会把综合生成模式的所有历史内容自动变为已核验。

本地模拟回归：

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest tests/test_report_modes.py tests/test_workflow_v07.py tests/test_reports_v06.py -q -p no:cacheprovider
```

修改上线时，需要重启后端和独立worker，并重新构建前端。仅刷新页面不会更新后台任务处理器。模型支持性判断和生成提示词均不保证绝对正确，最终内容由审阅人结合来源核对。
